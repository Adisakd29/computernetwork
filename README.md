# NetLab ห้องปฏิบัติการเครือข่ายคอมพิวเตอร์ (เวอร์ชัน 2.5)

แพลตฟอร์มแล็บเครือข่ายคอมพิวเตอร์สำหรับ ปวช./ปวส. มีแล็บท้ายคาบ 18 สัปดาห์ ห้องฝึก 12 ห้อง เทอร์มินัล Windows จำลอง Linux VM ที่รันในเบราว์เซอร์ ระบบสมาชิก (นักเรียน ครู ผู้ดูแลระบบ) และแดชบอร์ดครู

## Deploy ขึ้น Railway

### อัปโหลดโค้ด
อัปไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้น repository GitHub เดิม (ไม่ต้องอัป `node_modules` และ `public/v86`) Railway จะ deploy ใหม่ให้อัตโนมัติ ถ้ายังไม่ได้ทำขั้นตอนฐานข้อมูลด้านล่าง เว็บจะทำงานแบบผู้เยี่ยมชมเหมือนเดิม (ทำแล็บได้ แต่ไม่มีการเข้าสู่ระบบ)

### เพิ่มฐานข้อมูล PostgreSQL (ทำครั้งเดียว)
1. ในโปรเจกต์ Railway กด **+ Create** (หรือ New) → **Database** → **PostgreSQL** รอจนสถานะเป็น Active
2. เปิด service ของ NetLab (ตัวที่ deploy จาก GitHub) → แท็บ **Variables** → **New Variable**
3. เพิ่มตัวแปร 3 ตัว:
   - `DATABASE_URL` ค่า `${{Postgres.DATABASE_URL}}` (พิมพ์ตามนี้ Railway จะเชื่อมกับฐานข้อมูลให้เอง ถ้าตั้งชื่อ service ฐานข้อมูลเป็นอย่างอื่น ให้เปลี่ยนคำว่า Postgres เป็นชื่อนั้น)
   - `ADMIN_USERNAME` ชื่อผู้ใช้ผู้ดูแลระบบ เช่น `admin.kru`
   - `ADMIN_PASSWORD` รหัสผ่านที่เดายาก อย่างน้อย 12 ตัว
4. Railway จะ deploy ใหม่ เปิด `/vm-status` ต้องเห็น `"database": true`
5. เปิด `/teacher` เข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบ

บัญชีผู้ดูแลระบบถูกสร้างครั้งแรกจากตัวแปรเท่านั้น ถ้าเปลี่ยน `ADMIN_PASSWORD` ภายหลัง รหัสผ่านเดิมยังใช้อยู่ ให้เปลี่ยนรหัสผ่านจากเมนูในแดชบอร์ดแทน

## บทเรียน 18 สัปดาห์

แต่ละสัปดาห์มี 5 ขั้นตอนตามลำดับ: แบบทดสอบก่อนเรียน → เนื้อหา → แล็บท้ายคาบ → แบบทดสอบหลังเรียน → สรุป

- **แบบทดสอบก่อน/หลังเรียน** ข้อเดียวกัน 10 ข้อ (ระดับง่าย ปานกลาง ยาก) ส่งได้ครั้งเดียว ตรวจที่เซิร์ฟเวอร์ แบบทดสอบก่อนเรียนไม่เฉลย ส่วนหลังเรียนเฉลยพร้อมคำอธิบายทุกข้อ ครูให้ทำหลังเรียนใหม่ได้ที่แท็บ "ก่อน–หลังเรียน"
- **เนื้อหา** มีจุดประสงค์ สมรรถนะ แผนภาพ ตัวอย่างการใช้งานจริง สื่อ Interactive แบบฝึกหัดระหว่างเรียน (ตอบได้ไม่จำกัด เฉลยทันที) และสรุป ระบบนับว่าอ่านหัวข้อไหนแล้ว
- **แล็บท้ายคาบ** คือแล็บจับเวลาเดิม
- หน้าแดชบอร์ดมีไฟ LAN Tester 18 ดวงแสดงความคืบหน้า เขียว = เรียนจบ เหลือง = กำลังเรียน

เนื้อหาบทเรียนเขียนตามแผนการจัดการเรียนรู้ 10 หน่วย และผ่านการตรวจความถูกต้องทางเทคนิคอีกรอบแล้ว ครูควรอ่านทวนก่อนสอนจริง แก้ไขได้ที่ `content/lessons/wN.js` ตามรูปแบบใน `content/lessons/SPEC.md` แล้วรัน `npm run check:lessons` เพื่อตรวจรูปแบบ

## ใช้งานในห้องเรียน

1. ครูเข้า `/teacher` → **สร้างห้องเรียน** ระบบให้รหัสห้อง 6 ตัว
2. เพิ่มนักเรียนได้ 2 วิธี
   - **ครูสร้างบัญชีให้:** แท็บ "นักเรียน" วางรายชื่อ `เลขที่ ชื่อ–สกุล` บรรทัดละคน ระบบสร้างชื่อผู้ใช้และรหัสผ่านชั่วคราวให้ กด "พิมพ์บัตรรายชื่อ" แจกนักเรียน นักเรียนต้องตั้งรหัสผ่านใหม่เมื่อเข้าครั้งแรก
   - **นักเรียนสมัครเอง:** บอกรหัสห้องกับนักเรียน ให้กด "สมัครด้วยรหัสห้อง" ที่หน้าแรก ปิดรับสมัครได้ที่แท็บ "ตั้งค่าห้อง"
3. แท็บ "งานที่มอบหมาย" เลือกแล็บและกำหนดวันส่ง นักเรียนจะเห็นงานบนหน้าแรก
4. แท็บ "ก่อน–หลังเรียน" ดูคะแนนเฉลี่ยของห้องรายสัปดาห์ พัฒนาการรายบุคคล และกราฟเปรียบเทียบ
5. แท็บ "คะแนนแล็บ" ดูคะแนนรายคนทุกแล็บ ส่งออก Excel หรือพิมพ์เป็น PDF คลิกช่องคะแนนเพื่อให้นักเรียนทำแล็บนั้นใหม่
6. แท็บ "ข้อที่ผิดบ่อย" ดูข้อที่นักเรียนตอบผิดมากที่สุดและคำตอบผิดที่พบบ่อย
7. นักเรียนลืมรหัสผ่าน: แท็บ "นักเรียน" → รีเซ็ตรหัสผ่าน

ผู้ดูแลระบบสร้างบัญชีครูคนอื่นได้ที่เมนู "บัญชีครู" ครูแต่ละคนเห็นเฉพาะห้องเรียนของตัวเอง ผู้ดูแลระบบเห็นทุกห้อง

## ห้องจำลอง คลังข้อสอบ และการสอบ (Phase 4)

- **ห้องปฏิบัติการจำลอง** (เมนูซ้าย) มี 5 ชุด รวม 35 ภารกิจ: ออกแบบเครือข่าย (ลากวางอุปกรณ์ เดินสาย ตั้ง IP ส่ง Ping จริงในเครื่องจำลอง), คำนวณ Subnet (โจทย์สุ่มทุกครั้ง พร้อมวิธีทำทีละขั้น), เข้าหัวสาย RJ-45, ใช้คำสั่ง Windows/Linux กับเครือข่ายจำลอง และแก้ปัญหาเครือข่าย ทุกภารกิจตรวจที่เซิร์ฟเวอร์ เก็บคะแนนดีที่สุด ครูดูได้ที่แท็บ "ห้องจำลอง"
- **ฝึกทำข้อสอบ** เลือกหน่วย ระดับความยาก และรูปแบบ ตอบแล้วรู้ผลทันทีพร้อมคำอธิบายและคำตอบที่ถูก ไม่มีผลต่อคะแนน
- **การสอบ** ครูสร้างที่แท็บ "การสอบ" ของห้องเรียน: เลือกหน่วย จำนวนข้อ ง่าย/กลาง/ยาก รูปแบบข้อสอบ เวลาสอบ วันเปิด–ปิด และเลือกว่าจะแสดงเฉลยหลังส่งหรือไม่ นักเรียนแต่ละคนได้ชุดข้อสุ่มไม่ซ้ำกัน ทำได้ครั้งเดียว ระบบบันทึกคำตอบอัตโนมัติ หมดเวลาแล้วส่งให้เอง ครูดูคะแนน วิเคราะห์รายข้อ (ร้อยละตอบถูก คำตอบผิดที่พบบ่อย) ส่งออก Excel เพิ่มเวลาให้รายคน หรือให้สอบใหม่ได้
- ตั้งตัวแปร `APP_SECRET` (สตริงสุ่มยาว ๆ) ใน Railway เพื่อใช้เซ็นโจทย์สุ่มของห้องจำลอง ถ้าไม่ตั้ง ระบบสร้างจาก `DATABASE_URL` และ `ADMIN_PASSWORD` ให้แทน

## XP เหรียญ ภารกิจประจำสัปดาห์ และการวิเคราะห์ผล (Phase 5)

- **XP และเลเวล** คิดจากคะแนนที่เซิร์ฟเวอร์ตรวจแล้วเท่านั้น (แล็บ บทเรียน แบบทดสอบ ห้องจำลอง โหมดฝึก การสอบ ภารกิจประจำสัปดาห์) แก้ข้อมูลในเบราว์เซอร์ไม่ได้ ทำข้อเดิมซ้ำไม่ได้ XP เพิ่ม นักเรียนดูที่มาของ XP ได้ในหน้า "ความก้าวหน้าของฉัน"
- **เหรียญรางวัล 21 เหรียญ** 5 กลุ่ม (แล็บ บทเรียน ห้องจำลอง ข้อสอบ ความสม่ำเสมอ) แต่ละเหรียญแสดงความคืบหน้า ได้แล้วระบบแจ้งเตือนครั้งเดียว
- **ภารกิจประจำสัปดาห์** 3 เป้าหมาย เปลี่ยนทุกวันจันทร์ (เวลาไทย) เป้าหมายละ 20 XP ครบทุกเป้าหมายรับเพิ่ม 40 XP
- **วันต่อเนื่อง (Streak)** และปฏิทินวันที่เข้าเรียน 12 สัปดาห์ นับจากวันที่ทำกิจกรรมจริงในระบบ
- **ภารกิจแนะนำ** ระบบเลือกหน่วยที่ควรทบทวน การสอบที่ยังไม่ส่ง และภารกิจห้องจำลองถัดไปให้
- **กระดานคะแนน** ปิดไว้เป็นค่าเริ่มต้น ครูเปิดได้ที่แท็บ "ตั้งค่าห้อง" นักเรียนเห็นเฉพาะ 10 อันดับแรกและอันดับของตัวเอง ชื่อเพื่อนแสดงเฉพาะคนที่เลือกเปิดเผยชื่อเอง แสดงเฉพาะ XP (สัปดาห์นี้/ทั้งหมด) ไม่แสดงคะแนนสอบ
- **แท็บ "วิเคราะห์ผล" ของครู**: ความเข้าใจรายหน่วยและรายรูปแบบข้อสอบ จำนวนนักเรียนที่เข้าเรียนรายวัน 28 วัน รายชื่อนักเรียนที่ควรดูแล (ไม่ได้เข้าเรียน 7 วัน, ความเข้าใจต่ำกว่า 50% ในหน่วยที่มีข้อมูลอย่างน้อย 5 ข้อ, ค้างงานเลยกำหนด) ตารางรายคนพร้อมความเข้าใจรายหน่วย และส่งออก Excel
- วันเริ่มสัปดาห์และวันต่อเนื่องใช้เวลาไทย เปลี่ยนได้ด้วยตัวแปร `APP_TZ` (เช่น `Asia/Bangkok`)

## ใช้งานบนมือถือและแท็บเล็ต (2.4)

- มือถือ: แถบเมนูล่าง (หน้าแรก บทเรียน จำลอง ข้อสอบ เมนู) และเมนูเต็มแบบลิ้นชักที่มีปุ่มปิด ปิดได้ด้วยการแตะด้านนอก หรือกด Esc เปิดเมนูแล้วหน้าด้านหลังไม่เลื่อน
- แท็บเล็ตและคอมพิวเตอร์: เมนูด้านซ้ายย่อเป็นแถบไอคอนได้ (ปุ่มลูกศรมุมบน) ระบบจำการเลือกไว้ในเครื่อง
- ห้องจำลองใช้นิ้วได้ทั้งหมด: วางอุปกรณ์ด้วยการแตะ ซูมด้วยสองนิ้ว โหมดเต็มจอ แผงตั้งค่าแบบเลื่อนขึ้นจากด้านล่าง ปุ่มขยายหัว RJ-45 ปุ่มคำสั่งลัดและคัดลอกผลลัพธ์ในเทอร์มินัล
- ลืมรหัสผ่าน: นักเรียนกด "ลืมรหัสผ่าน?" ที่หน้าเข้าสู่ระบบ คำขอไปที่แดชบอร์ดครู (ป้าย "ขอรหัส" ที่ชื่อห้อง และกล่องคำขอในแท็บนักเรียน) ครูตรวจตัวตนแล้วกด "ตั้งรหัสชั่วคราว" ระบบตอบเหมือนกันทุกกรณีจึงใช้เดาชื่อผู้ใช้ไม่ได้
- ผู้เยี่ยมชม: มีแถบเตือนว่าคะแนนเก็บเฉพาะในเบราว์เซอร์ เมื่อสมัครหรือเข้าสู่ระบบ ระบบเสนอให้ผูกงานที่ทำไว้เข้าบัญชี โดยตรวจคำตอบทุกข้อใหม่ที่เซิร์ฟเวอร์ แล็บที่นำเข้าจะมีเครื่องหมาย * ในตารางคะแนนของครู (แบบทดสอบก่อน/หลังเรียนนำเข้าไม่ได้)

## Linux VM ทำงานอย่างไร

VM ใช้โปรเจกต์ [v86](https://github.com/copy/v86) ซึ่งจำลองเครื่อง x86 ด้วย WebAssembly **รันบนเครื่องของนักเรียนแต่ละคน** ไม่ได้รันบนเซิร์ฟเวอร์ จึงมีข้อดีคือ

- นักเรียนแต่ละคนได้ Linux ของตัวเอง เป็น root ได้ ทำพังก็กดรีสตาร์ท ไม่กระทบคนอื่น
- เซิร์ฟเวอร์ Railway แค่ส่งไฟล์ให้ ใช้ทรัพยากรน้อย ค่าใช้จ่ายต่ำ
- เบราว์เซอร์จะเก็บไฟล์ VM ไว้ในแคช ครั้งต่อไปโหลดเร็วขึ้น

Railway รัน VM บนเซิร์ฟเวอร์โดยตรงไม่ได้ เพราะไม่อนุญาต nested virtualization และ privileged container

ขั้นตอนในห้องเรียน: เข้าห้องที่มีป้าย Linux VM → กด "เปิด Linux VM" → รอจนเห็น prompt → กด "เตรียมโจทย์" → คลิกที่หน้าจอดำแล้วพิมพ์คำสั่งตามโจทย์

ข้อแนะนำ: ใช้ Chrome หรือ Edge รุ่นใหม่ ให้นักเรียนเปิด VM ทีละแท็บ และให้ครูเปิดหน้าเว็บทิ้งไว้ก่อนคาบสักครั้งเพื่อทดสอบ

## ถ้า VM เปิดไม่ได้

**ขั้นแรก เปิดหน้า `/vm-status`** เช่น `https://ชื่อเว็บ.up.railway.app/vm-status` จะเห็นว่าไฟล์ VM ตัวไหนขาด (`"ok": false`)

**ถ้าขาด `buildroot-bzimage.bin`** แปลว่าดาวน์โหลดอิมเมจ Linux ไม่สำเร็จ ระบบจะลองดาวน์โหลดใหม่ทุกครั้งที่เซิร์ฟเวอร์เริ่มทำงาน ให้ลองกด Redeploy ใน Railway ก่อน ถ้ายังไม่ได้ แก้ได้ 2 วิธี

1. ดาวน์โหลดไฟล์ `buildroot-bzimage68.bin` จากเว็บของ v86 ด้วยคอมพิวเตอร์ของครู แล้วอัปไว้ใน GitHub Releases ของ repo นี้ จากนั้นตั้ง Environment Variable ใน Railway ชื่อ `VM_IMAGE_URL` เป็นลิงก์ดาวน์โหลดของไฟล์นั้น แล้ว Redeploy
2. หรือเปลี่ยนชื่อไฟล์เป็น `buildroot-bzimage.bin` วางใน `public/v86/` ลบบรรทัด `public/v86/` ออกจาก `.gitignore` แล้วอัปขึ้น GitHub

**ถ้าขาดทุกไฟล์** แปลว่าสคริปต์เตรียมไฟล์ไม่ได้ทำงาน ตรวจว่า Start Command ใน Railway เป็น `npm start` (ไม่ใช่ `node server.js` เพราะจะข้ามขั้นตอนเตรียมไฟล์)

**บูตแล้วหน้าจอค้างหรือขึ้นถามชื่อผู้ใช้** พิมพ์ `root` แล้วกด Enter

**กด "เตรียมโจทย์" แล้วไม่มีอะไรเกิดขึ้น** คลิกที่หน้าจอดำแล้วกด Enter หนึ่งครั้ง หรือรอให้บูตเสร็จก่อนแล้วกดใหม่

**คำสั่งบางตัวไม่มี** อิมเมจนี้ใช้ BusyBox ซึ่งมีคำสั่งพื้นฐาน (ip, ping, grep, adduser, chmod, md5sum, sha256sum, base64) ถ้าคำสั่งใดไม่มี แจ้งนักเรียนว่าข้อนั้นตอบจากความรู้ได้ เพราะคำตอบทุกข้อเป็นไปตามหลักการของ Linux

## แล็บท้ายคาบ 18 สัปดาห์

หน้าแรกมี 2 แท็บ คือ **แล็บท้ายคาบ 18 สัปดาห์** (ค่าเริ่มต้น) และ **ห้องฝึก 12 ห้อง** แล็บท้ายคาบเรียงตามแผนการจัดการเรียนรู้วิชาเครือข่ายคอมพิวเตอร์ 10 หน่วย 18 สัปดาห์ ใช้เวลาแล็บละ 15 นาที (สัปดาห์ที่มีเทอร์มินัลจำลอง 20 นาที และสัปดาห์ที่มี Linux VM 25 นาที)

| สัปดาห์ | หน่วย | กิจกรรมพิเศษ |
|---|---|---|
| 1–3 | 1–3 | จับคู่องค์ประกอบ อุปกรณ์ หัวต่อ องค์กรมาตรฐาน เรียงชั้น OSI |
| 4–5 | 4 | จับคู่มาตรฐาน Ethernet เรียงสี T568A/T568B |
| 6–7 | 5 | ตั้งค่าความปลอดภัย Wi-Fi Router จำลอง |
| 8–9 | 6 | เทอร์มินัล Windows จำลอง ตั้งค่า IPv4 แบบ Static |
| 10–12 | 7 | Linux VM (สัปดาห์ 11–12) |
| 13–14 | 8 | ipconfig, ping, tracert, netstat, nslookup และ Linux VM แก้ปัญหา |
| 15–16 | 9 | สร้างกฎ Windows Firewall จำลอง และ Linux VM ตรวจ checksum |
| 17–18 | 10 | net user, net localgroup และ Linux VM กำหนดสิทธิ์ |

แก้โจทย์แล็บท้ายคาบได้ใน `content/labs.js` ค้นหา `const WEEKS` เวลาของแล็บท้ายคาบกำหนดในบรรทัด `w.minutes = ...` ใต้ `WEEKS`

## การบันทึกคะแนน

นักเรียนที่เข้าสู่ระบบ: คะแนนบันทึกในฐานข้อมูล ใช้เครื่องไหนก็ทำต่อได้ ครูเห็นในแดชบอร์ดทันที ผู้เยี่ยมชม (ไม่เข้าสู่ระบบ): คะแนนเก็บในเบราว์เซอร์เครื่องนั้น ต้องถ่ายภาพ "ใบสรุปผล" ส่งครูเหมือนเวอร์ชันเดิม
