## การทำงาน
- ตอนเริ่มเซิร์ฟเวอร์ครั้งแรกหลัง deploy (migration `schedule-2569-2` ครั้งเดียว) ทุกห้องเรียนที่มีอยู่ได้วันเปิดของสัปดาห์ที่ยังไม่มีวันเปิด วันที่ครูตั้งไว้เองไม่ถูกแทน บันทึกในประวัติกติกาของห้อง ห้องที่สร้างใหม่ระหว่างภาคเรียนได้ตารางนี้อัตโนมัติ
- วันเปิดล็อกสัปดาห์นั้นทั้งในห้องที่เรียนตามลำดับและห้องที่ไม่บังคับลำดับ (เดิมใช้ได้เฉพาะห้องที่เรียนตามลำดับ) ล็อกที่เซิร์ฟเวอร์ทั้งเนื้อหา แบบทดสอบ ฝึกปฏิบัติ และภารกิจ
- ห้องที่เรียนตามลำดับ: สัปดาห์จะเปิดเมื่อ **ถึงวัน และ** ผ่านสัปดาห์ก่อนหน้าแล้ว
- สัปดาห์ที่นักเรียนผ่านแล้วยังเปิดอยู่เสมอ คะแนนเดิมไม่หาย
- ครูไม่ถูกล็อก ครูปลดล็อกให้นักเรียนรายคนหรือทั้งห้องก่อนวันได้ และแก้/ล้างวันได้ที่แท็บ "เส้นทางการเรียน" > "วันเปิดบทเรียนรายสัปดาห์" (มีปุ่ม "เติมวันเปิดทุกสัปดาห์" จากวันเรียนครั้งแรก ทุก N วัน) เช่น เลื่อนวันหยุดราชการ หรือสอบกลางภาค
- การแก้วันเปิดส่งเฉพาะสัปดาห์ที่เปลี่ยน (เดิมการส่งวันเปิดแทนทั้งชุด)

## Migration Plan
- ไม่เปลี่ยนโครงสร้างฐานข้อมูล แก้เฉพาะ `classes.path.openDates` ของห้องเรียน ไม่แตะข้อมูลนักเรียน
- สำรองก่อน deploy (ปุ่มสำรองข้อมูลของผู้ดูแล หรือ `pg_dump`)
- ย้อนกลับ: แก้หรือล้างวันในหน้าครู หรือกู้ค่า `classes.path` จากไฟล์สำรอง
- ตรวจหลัง deploy: log มีบรรทัด `Class timetable: open dates set for N class(es), week 1 opens 2026-10-26`

## การทดสอบ
- `tests/path.test.js` เพิ่ม: วันที่คำนวณถูก (สัปดาห์ 18 = 22 ก.พ. 2570), วันที่ครูตั้งไว้ไม่ถูกแทน, บันทึกประวัติ, ทำครั้งเดียว, ล็อกแม้ห้องไม่บังคับลำดับ, เซิร์ฟเวอร์ปฏิเสธเนื้อหาก่อนวัน (403), ครูปลดล็อกก่อนวันได้, ห้องใหม่ได้ตาราง, ครูล้างวันได้
- ทดสอบในเบราว์เซอร์กับห้องที่สร้างแบบเดิม (ไม่บังคับลำดับ): หน้าบทเรียนแสดง "บทเรียนนี้เปิดวันที่ 2 พฤศจิกายน 2569" ทั้งจอคอมและมือถือ 360px ไม่มีแถบเลื่อนแนวนอน และปุ่มเติมวันในหน้าครูเติม 18 สัปดาห์ถูกต้อง
- ชุดทดสอบอัตโนมัติอื่นปิดตารางเรียนไว้ (`TIMETABLE=off`) เพื่อไม่ให้ผลขึ้นกับวันที่รัน
