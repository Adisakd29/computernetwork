# รายงาน NetLab 2.9: ยุบห้องฝึก 12 ห้องเข้ากับบทเรียน 18 สัปดาห์

**ผลลัพธ์:** เมนูการเรียนเหลือ "บทเรียน 18 สัปดาห์" เมนูเดียว กิจกรรมทุกข้อของห้องฝึกเดิมยังอยู่ (บางข้อรวมกับข้อเดียวกันในแล็บ) คะแนนและประวัติเดิมไม่ถูกลบ

รายละเอียดเชิงเทคนิคทั้งหมดอยู่ใน `docs/MERGE-ROOMS-2.9.md`

## 1. พบเนื้อหาหรือข้อสอบซ้ำจริงกี่รายการ

| แหล่ง | ซ้ำจริง | หมายเหตุ |
|---|---|---|
| ห้องฝึก กับ แล็บท้ายคาบ | **18 ข้อ** | คำถามเดียวกัน เฉลยเดียวกัน ใช้เครื่องจำลองเดียวกัน |
| ภารกิจ Linux VM ห้อง 9–12 กับแล็บสัปดาห์ 12, 14, 16, 18 | **22 ภารกิจ (4 ชุด)** | เป็นชุดเดียวกันอยู่แล้วในโค้ด แต่คะแนนแยกเก็บ ทำให้นักเรียนต้องทำ 2 ครั้ง |
| ห้องฝึก กับ คลังข้อสอบ / แบบทดสอบก่อน-หลัง / แบบฝึกหัดในบทเรียน | 0 | มี 1 ข้อคล้ายกับแบบทดสอบหลังเรียนสัปดาห์ 10 แบบทดสอบใช้วัดผล จึงคงไว้ |
| ภายในคลังข้อสอบ (462 ข้อที่ใช้งาน) | 0 | ไม่มีโจทย์ข้อความซ้ำกัน |
| แบบทดสอบก่อน/หลังเรียนข้ามสัปดาห์ | 0 | |

**คู่ที่หัวข้อเดียวกันแต่วัดคนละทักษะหรือคนละข้อมูล (11 คู่) เก็บไว้ทั้งหมด** เช่น T568A กับ T568B, IEEE 802.3 กับ 802.11 และการเลือกการเข้ารหัสกับการตั้งค่าจริงในฟอร์ม

**การสุ่มข้อสอบไม่ได้แก้:** ระบบเดิมสุ่มแบบไม่ซ้ำในชุดเดียวกันอยู่แล้ว และตัดข้อฉบับเก่า (retired) ออก

## 2. กิจกรรมที่ถูกรวม

- **ข้อซ้ำ 18 ข้อ:**
  - เหลือข้อในแล็บท้ายคาบ ข้อในห้องฝึกถูกซ่อน (ไม่ได้ลบ)
  - 5 ข้อใช้คำอธิบายที่ละเอียดกว่าจากฉบับห้องฝึก
  - ภารกิจท้าทายบอกว่าข้อเหล่านี้ไปอยู่แล็บสัปดาห์ใด
- **VM 4 ชุด (22 ภารกิจ):** ทำที่แล็บท้ายคาบสัปดาห์ 12, 14, 16, 18 ครั้งเดียว
- **ความยาวภารกิจ:** ห้อง 9, 10, 12 สั้นลงจากการรวมข้อซ้ำ เวลาจับเวลาของห้อง 9–12 ลดลง (30→15, 45→30, 35→25, 35→20 นาที) มีผลกับการเริ่มครั้งใหม่เท่านั้น

## 3. กิจกรรมที่ถูกย้ายไปสัปดาห์ใด

| ห้องเดิม | ภารกิจท้าทายในสัปดาห์ | ลิงก์จากสัปดาห์ | ข้อที่เหลือ |
|---|---|---|---|

เลือกสัปดาห์ตามจุดประสงค์การเรียนรู้ของบทเรียน ส่วนใหญ่ตรงกับ mapping ที่ครูให้ไว้ เหตุผลของห้องที่ต่างไปอยู่ใน `MERGE-ROOMS-2.9.md` หัวข้อ 3

**แต่ละสัปดาห์มี 6 ขั้น:** ก่อนเรียน → เนื้อหา (มีแบบฝึกหัดระหว่างเรียน) → ฝึกปฏิบัติ → ภารกิจท้าทาย → หลังเรียน → สรุปผล
- **ฝึกปฏิบัติ:** แล็บท้ายคาบ, เทอร์มินัลหรือ Linux VM และลิงก์ภารกิจห้องจำลองของสัปดาห์
- **ภารกิจท้าทาย:** การ์ดแสดงจำนวนข้อ เวลา คะแนนเต็ม สถานะ และคะแนนที่ได้
- **สรุปผล:** คะแนนทุกขั้น หัวข้อที่ควรทบทวน และระดับทักษะที่เกี่ยวข้อง

**ลิงก์ห้องจำลองเปิดตรงไปยังภารกิจ** เช่น `#/sim/topology/t3` ทั้ง 5 ห้องจำลองรองรับแล้ว

**ภารกิจท้าทายไม่บังคับ:** ไม่ได้ตั้งให้ต้องทำก่อนแบบทดสอบหลังเรียน เพื่อไม่เปลี่ยนเกณฑ์ "เรียนจบสัปดาห์" และสถานะเดิมของนักเรียน ถ้าครูต้องการบังคับ ใช้การมอบหมายงานในหน้าครูได้เหมือนเดิม

## 4. ภารกิจ Linux VM ย้ายครบหรือไม่

**ครบ 27 ข้อ:**
- ห้อง 5 จำนวน 5 ข้อ อยู่ในภารกิจท้าทายสัปดาห์ 8
- ห้อง 9–12 จำนวน 22 ข้อ อยู่ในแล็บท้ายคาบสัปดาห์ 12, 14, 16, 18

**ไม่มีข้อใดเปลี่ยนเป็นปรนัย:** ยังใช้ปุ่มเปิด VM คำสั่ง "เตรียมโจทย์" และการตรวจคำตอบจาก VM เดิมทุกข้อ

**ข้อจำกัดของการทดสอบ:** ไฟล์ Linux kernel ของ v86 ดาวน์โหลดจากเครื่องทดสอบนี้ไม่ได้ จึงยังไม่ได้ทดสอบการบูต VM จริงรอบนี้ ที่ทดสอบแล้วคือ
- ภารกิจและปุ่ม VM แสดงครบในหน้าที่ถูกต้อง
- เซิร์ฟเวอร์ตรวจคำตอบของทุกข้อได้

ส่วนบูต VM ไม่ได้แก้ในรอบนี้ ครูควรเปิดแล็บสัปดาห์ 12 บนเว็บจริงหลัง deploy เพื่อลอง VM สักครั้ง

## 5. ระบบคะแนนเดิมได้รับผลกระทบหรือไม่

**ไม่มีคะแนนหรือประวัติถูกลบ:**
- คีย์ข้อและรหัสห้องเดิมใช้ต่อ แถวคะแนนเดิมทุกแถวยังอยู่
- migration สำรองตารางคะแนนทั้งตารางก่อนทำ ทำครั้งเดียว และย้อนกลับได้

**นักเรียนที่เคยตอบข้อซ้ำหรือภารกิจ VM ในห้องฝึก:**
- ได้เครดิตที่ข้อในแล็บสัปดาห์ด้วยคะแนนเดิม ไม่ต้องทำซ้ำ
- **XP ไม่เปลี่ยน** ทดสอบแล้วว่าเท่าเดิมทุกคน

**สิ่งที่ครูจะเห็นต่างไป:**
- คะแนนเต็มของห้อง 2, 4, 6, 9, 10, 12 ลดลงตามจำนวนข้อที่ซ่อน
- นักเรียนที่เคยตอบข้อซ้ำถูกทั้งสองที่ จะเห็นคะแนนข้อนั้นครั้งเดียว ผลรวมในตารางคะแนนแล็บของคนนั้นจึงอาจลดลง ซึ่งเป็นการแก้การนับซ้ำเดิม
- ชื่อคอลัมน์เปลี่ยนเป็น "ท้าทาย ส.N" หน้ามอบหมายงานแสดงเลขห้องเดิมกำกับ
- งานที่มอบหมายไว้กับห้องฝึกเดิมยังใช้ได้

## 6. รายการที่ยังย้ายไม่สำเร็จหรือยังไม่ได้ทดสอบ

- **ย้ายครบทุกข้อ** ไม่มีกิจกรรมค้าง
- **ยังไม่ได้ทดสอบ:**
  - การบูต Linux VM จริง (เหตุผลในข้อ 4)
  - มือถือ/แท็บเล็ตจริง (ทดสอบด้วยการจำลองหน้าจอใน Chromium เท่านั้น)
  - Firefox/WebKit (GitHub Actions ตั้งไว้ให้ทดสอบตอนอัปขึ้น GitHub)
  - การรัน migration กับฐานข้อมูลจริงบน Railway (ทดสอบกับข้อมูลจำลองใน PostgreSQL 16 แล้ว)
- **ก่อน deploy ควรทำ:**
  - สำรองข้อมูลด้วย `/api/admin/backup` หรือ `pg_dump`
  - ดูตัวเลขที่จะเปลี่ยนด้วย `node scripts/merge-rooms.js --plan`
- **ตาราง `backup_29_task_progress`:** เก็บไว้ ให้ครูหรือผู้ดูแลลบเองเมื่อมั่นใจ
