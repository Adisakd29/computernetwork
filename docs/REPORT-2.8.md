# รายงาน NetLab 2.8: ปรับหลักสูตรและห้องปฏิบัติการเสมือน

**แนวทางที่ครูเลือก:** "คงแผนเดิม แล้วเติมหัวข้อที่ขาด" ลำดับ 18 สัปดาห์ / 10 หน่วยตามแผนการสอนทางการไม่เปลี่ยน หัวข้อในหนังสือที่ยังขาดถูกเติมเป็นเนื้อหาเสริมและแล็บในสัปดาห์ที่ใกล้ที่สุด

**ข้อจำกัดที่ยึดถือตลอดงาน**
- ไม่คัดลอกข้อความจากหนังสือ ใช้สารบัญ (`docs/book-toc.md`) เป็นรายการตรวจเท่านั้น และไม่อ้างว่าเนื้อหาที่เขียนใหม่มาจากหนังสือโดยตรง
- ไม่ลบบทเรียน คำถาม หรือฟีเจอร์เดิม
- ไม่เรียกเทอร์มินัลจำลองว่าเป็น VM
- คะแนนคิดที่เซิร์ฟเวอร์ทั้งหมด

## ระยะที่ 1: วิเคราะห์หลักสูตร (Curriculum Mapping)

- **ผลงาน:** `docs/CURRICULUM-MAP.md` เทียบ 115 หัวข้อของหนังสือ 12 บทกับบทเรียน แบบฝึก แผนภาพ และแล็บที่มีอยู่ และเทียบแล็บรายสัปดาห์ W1–W18 ที่ครูต้องการกับสิ่งที่มี
- **สถานะก่อน 2.8:** เต็ม 46 / บางส่วน 48 / ไม่มี 21 หัวข้อ ครอบคลุม 61%
- **สถานะหลัง 2.8:** เต็ม 87 / บางส่วน 25 / ไม่มี 3 หัวข้อ ครอบคลุม 87%
  - หัวข้อที่สถานะเปลี่ยน 46 หัวข้อ แสดงในส่วนที่ 4 ของเอกสาร
  - ประเมินซ้ำตามเกณฑ์เดิม ถ้าเนื้อหาใหม่กล่าวถึงเพียง 1–2 ประโยค ยังนับเป็น "บางส่วน"
- **ยังไม่ครอบคลุมเต็ม**
  - บท 10: Subnetting, CIDR และ NAT ในมุมของหนังสือ บทเรียนเดิมมีเนื้อหาส่วนนี้อยู่แล้ว แต่ยังไม่มีหัวข้อเสริมของสัปดาห์ 8
  - บท 9: DCF และ RTS/CTS
  - หัวข้อประวัติศาสตร์หรือเทคโนโลยีเลิกใช้ (Token Bus, 56K modem) ตั้งใจไม่ขยาย
- **การแก้เนื้อหาเดิม:** เพิ่มแถว IETF ในตารางองค์กรมาตรฐานของสัปดาห์ 3
  - ตรวจข้อเสนอเรื่องความเร็ว Wi-Fi 7 แล้วคงตัวเลขเดิมของบทเรียน (ประมาณ 23 Gb/s ต่อย่านความถี่)
  - เหตุผล: มาตรฐาน 802.11be ฉบับสุดท้ายใช้ 8 spatial streams ส่วนตัวเลข 46 Gbps มาจากร่างแรกที่ใช้ 16 streams

## ระยะที่ 2: เนื้อหาเสริมแบบลงมือทำ

- **หัวข้อเสริม 15 หัวข้อ**
  - สัปดาห์ 1 (2), 2 (3), 3 (2), 4 (4), 10 (2), 16 (2)
  - มีแบบฝึกตรวจคำตอบในหัวข้อ 46 ข้อ แผนภาพ 11 ภาพ และแล็บโต้ตอบ 10 แล็บ
  - เพิ่มข้อสอบในคลัง 29 ข้อ (ใช้ id ใหม่ ไม่ทับข้อเดิม)
  - มีคู่มือหัวข้อ (คำถามนำ จุดประสงค์ คำศัพท์ สรุป) ครบทั้ง 15 หัวข้อ
- **แล็บโต้ตอบคำนวณผลจริงทั้งหมด**
  - สัญญาณ: แอมพลิจูด ความถี่ เฟส และ ASK/FSK/PSK
  - Multiplexing แบบ FDM/TDM
  - Parity / Checksum / CRC จากบิตจริง พร้อมการทำบิตให้เสีย
  - ARQ 3 แบบ ตามลำดับเฟรมที่หาย
  - เทอร์มินัลอนุกรม RS-232 (baud, parity, stop bit ต้องตรงกันจึงอ่านออก)
  - Circuit กับ Packet switching
  - Jitter buffer
  - ชั้น Transport (UDP/TCP/SCTP) และ Socket
  - การเข้ารหัส Caesar/XOR และการตรวจใบรับรองจำลอง
- **การแสดงผล**
  - ต่อท้ายบทเรียนหลัง "เนื้อหาเสริมและแล็บเพิ่มเติม" พร้อมป้าย "เสริม"
  - ไม่นับในความคืบหน้าบังคับ จึงไม่เปลี่ยนเกณฑ์ผ่านบทเรียนและคะแนนเดิม
- **สัดส่วนฝึกปฏิบัติ 70%:** ทุกสัปดาห์มีแล็บและห้องจำลอง และระดับทักษะให้น้ำหนักงานลงมือทำ 70% แต่เวลาเรียนจริงในคาบเป็นเรื่องที่ครูจัด ซอฟต์แวร์ไม่ได้บังคับหรือวัดเวลา

## ระยะที่ 3: ห้องปฏิบัติการเสมือนสามระดับ

รายละเอียดอยู่ใน `docs/LAB-ARCHITECTURE.md`

- **ระดับ A Visualization:** สื่อโต้ตอบในบทเรียน
- **ระดับ B Simulator:** NetSim ที่มีสถานะจริงและตรวจซ้ำบนเซิร์ฟเวอร์ ความสามารถใหม่
  - ปิดเครื่อง
  - Hub จริงและ Collision domain
  - กฎ Firewall บน Router
  - รหัสผ่าน Wi-Fi และ Client isolation
- **ระดับ C Real VM:** Linux ด้วย v86 ที่มีอยู่แล้ว
  - รันบนเครื่องนักเรียน ไม่มีการ์ดเครือข่ายออกภายนอก
  - เทอร์มินัล Windows เป็น Simulator ไม่ได้เรียกว่า VM
- **ห้องแล็บหลายเครื่องบนเซิร์ฟเวอร์ (ยังไม่ได้ทำ)**
  - Railway ไม่อนุญาต privileged container และ nested virtualization
  - เอกสารเสนอ 4 ทางเลือก พร้อมข้อดี ข้อเสีย และค่าใช้จ่ายโดยประมาณ ให้ครูตัดสินใจก่อน
- **UX ของห้องจำลองเครือข่าย**
  - พื้นที่วางอุปกรณ์ แผงอุปกรณ์ และแผงคุณสมบัติที่ตรวจค่าทันที
  - แท็บ ปัญหาที่พบ / ทดสอบ (ping, tracert) / ข้อกำหนด / บันทึก
  - Undo/Redo, ซูม, จัดพอดีจอ, เต็มจอ, ซูมด้วยสองนิ้ว
  - บันทึกงานในเครื่อง และล้างแผนผัง
  - ปุ่มบนจอสัมผัสสูงอย่างน้อย 44 px

## ระยะที่ 4: ประเมินตามทักษะ, Rubric และครูตรวจ

- **ระดับทักษะ 10 ด้าน** (`server/skills.js`)
  - ระดับ Beginner / Developing / Proficient / Advanced
  - คิดจากหลักฐานจริงเท่านั้น: ภารกิจในห้องจำลอง ห้องฝึก และคำตอบในคลังข้อสอบ (ข้อล่าสุด)
  - น้ำหนักลงมือทำ 70% ความรู้ 30%
  - ทำข้อสอบอย่างเดียวได้สูงสุด Beginner
  - ทุกระดับแสดงเหตุผล งานที่ดีที่สุด และสิ่งที่ต้องทำต่อ
- **การแสดงผลระดับทักษะ**
  - นักเรียนเห็นที่หน้า "ความก้าวหน้าของฉัน"
  - ครูเห็นตารางนักเรียน × ทักษะในแท็บวิเคราะห์ผล
- **ภารกิจที่มี Rubric และครูตรวจ**
  - **t9 โครงงานปิดท้าย (สัปดาห์ 18):** อัตโนมัติ 40 คะแนนจาก Rubric 10 ข้อ ได้แก่ อุปกรณ์ สายสัญญาณ แผน IP/VLSM การตั้งค่า Gateway/DNS Connectivity matrix Firewall Wi-Fi การแก้เหตุขัดข้อง และรายงาน
  - **x14 สุ่มเหตุขัดข้อง (สัปดาห์ 17):** อัตโนมัติ 20 คะแนน บวกครูตรวจ 8 คะแนน (คุณภาพรายงานและการให้เหตุผล 5, ความเป็นมืออาชีพและการสื่อสาร 3)
- **การเก็บและตรวจงาน**
  - งานเก็บในตารางใหม่ `sim_submissions` ไว้ 5 ครั้งล่าสุดต่อคนต่อภารกิจ
  - ครูตรวจในแท็บ "ตรวจงานโครงงาน" ตรวจได้เฉพาะห้องของตัวเอง
  - คะแนนต้องอยู่ระหว่าง 0 ถึงคะแนนเต็มของเกณฑ์ (ปัดทีละ 0.5)
  - นักเรียนเห็นคะแนนและความเห็นของครู
- **โจทย์สุ่ม x14**
  - สร้างบนเซิร์ฟเวอร์ ลงลายเซ็น HMAC ผูกกับผู้ใช้ และหมดอายุใน 6 ชั่วโมง
  - เฉลยสร้างใหม่จาก nonce ด้วยกุญแจลับ ไม่ส่งไปยังเบราว์เซอร์
- **แก้ระหว่างระยะ:** เดิม API บังคับ token กับทุกภารกิจของห้องที่มีโจทย์สุ่ม ทำให้ x1–x13 ต้องขอ "ตั๋ว" ก่อนส่ง
  - เปลี่ยนเป็นบังคับเฉพาะภารกิจที่สุ่มจริง (`generatedMissions`)
  - ลบโค้ดขอตั๋วในหน้าเว็บออก

## ระยะที่ 5: ฐานข้อมูล (Migration)

- **เพิ่มเฉพาะตารางใหม่** `sim_submissions` และ index ด้วย `CREATE TABLE IF NOT EXISTS`
  - ทำงานเองเมื่อเซิร์ฟเวอร์เริ่ม
  - ไม่แก้หรือย้ายข้อมูลในตารางเดิม
- **คะแนนอัตโนมัติยังเก็บใน `sim_results`** เหมือนเดิม ตารางใหม่เก็บเฉพาะคะแนนครูและรายงาน
- **ข้อมูลส่วนตัวของผู้เรียน**
  - ลบบัญชีแล้วงานใน `sim_submissions` ถูกลบตาม (ON DELETE CASCADE)
  - การดาวน์โหลดข้อมูลของตัวเองรวมงานส่วนนี้ด้วย
- **ระดับทักษะไม่มีตาราง** คำนวณจากข้อมูลเดิมทุกครั้งที่เรียกดู จึงไม่ต้อง migrate

**API ใหม่ที่ทดสอบ**

- เก็บงาน 5 ครั้งล่าสุด
- ครูคนอื่นตรวจหรือดูไม่ได้ (404) และนักเรียนเรียก API ครูไม่ได้ (403)

- นักเรียนเห็นความเห็นของครู
- ทดสอบระดับทักษะ รวมถึงกฎแต่ละระดับ

**e2e ใหม่ (part9)**
- เปิดหัวข้อเสริมทั้ง 15 หัวข้อที่ 390 px และ 1366 px ไม่มีภาพเสีย ไม่ล้นจอแนวนอน และไม่มี JS error
- แล็บโต้ตอบ 7 ตัวเปลี่ยนผลเมื่อใช้งาน
- x14 บนมือถือ
- แผงทักษะ

- t9 เปิดได้ทั้งมือถือและเดสก์ท็อป

**ปัญหาที่ e2e พบและแก้แล้ว**
- **axe พบปัญหาการเข้าถึง 2 จุดในแล็บใหม่:** `aria-label` บน div ที่ไม่มี role และกล่องเลื่อนที่โฟกัสด้วยคีย์บอร์ดไม่ได้ แก้แล้ว และรัน axe ซ้ำได้ 0 violation
- **การค้นหาจากเมนูบนมือถือล้มเหลวเป็นบางครั้ง**
  - สาเหตุ: คลิกที่เกิดซ้ำ (ghost click) จากการแตะเปิดเมนูไปโดนปุ่มปิดเมนูซึ่งอยู่ตำแหน่งเดียวกัน
  - แก้โดยให้ปุ่มปิดไม่รับคลิกภายใน 250 ms หลังเปิดเมนู (คลิกซ้ำที่พบเกิดภายในประมาณ 60–100 ms) และให้ชุดทดสอบรอเมนูเปิดเสร็จก่อนพิมพ์

**ผล e2e รอบสุดท้าย (หลังแก้ทั้งสองจุด):** PASS ทุกชุด 376 รายการ

## สิ่งที่ยังไม่ได้ทดสอบหรือยังมีข้อจำกัด (แจ้งตามจริง)

- **ยังไม่ได้ทดสอบบนมือถือและแท็บเล็ตจริง** ทดสอบด้วยการจำลองหน้าจอและการสัมผัสใน Chromium เท่านั้น
- **Firefox และ WebKit ไม่ได้ติดตั้งในเครื่องทดสอบรอบนี้** จึงรัน smoke เฉพาะ Chromium แต่ GitHub Actions (`.github/workflows/tests.yml`) ตั้งไว้ให้รัน smoke บน Firefox และ WebKit ทุกครั้งที่อัปขึ้น GitHub ให้ดูผลที่แท็บ Actions ของ repo
- **เหตุขัดข้องของ t9 ไม่ได้สุ่มจากเซิร์ฟเวอร์**
  - คำนวณแบบ deterministic จากแผนผังตั้งต้นของผู้เรียน และเซิร์ฟเวอร์คำนวณซ้ำได้
  - ผู้ที่แก้คำขอ HTTP เองอาจเลือกเหตุขัดข้องได้ ส่วนนี้มีน้ำหนัก 3 จาก 40 คะแนน และครูตรวจรายงานประกอบ
- **ยังไม่ได้ทำห้องแล็บหลายเครื่องบนเซิร์ฟเวอร์ (VM/Container)** มีเพียงแผนและทางเลือกพร้อมค่าใช้จ่ายโดยประมาณ ราคาต้องตรวจอีกครั้งก่อนซื้อ
- **ยังไม่ได้ทดลองกับฐานข้อมูล production บน Railway**
  - ทดสอบกับ PostgreSQL 16 ในเครื่องทดสอบ
  - migration เป็นแบบเพิ่มตารางอย่างเดียว คาดว่าไม่กระทบข้อมูลเดิม แต่ควรสำรองข้อมูล (`/api/admin/backup`) ก่อน deploy
- **ยังไม่ได้ผ่านการตรวจของครูผู้สอน**
  - ทั้งความถูกต้องทางวิชาการของเนื้อหาเสริม 15 หัวข้อและข้อสอบ 29 ข้อ
  - เนื้อหาเขียนใหม่ทั้งหมด ไม่ได้คัดลอกจากหนังสือ ควรให้ครูอ่านทานก่อนใช้สอบจริง
