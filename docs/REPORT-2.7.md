# รายงาน NetLab 2.7: ระบบสมาชิกส่วนบุคคล, Google Sign-in และ Cursor Parallax

## สิ่งที่พบจากการตรวจระบบเดิม

- **บัญชีนักเรียน:** สร้างได้ 2 ทาง คือครูสร้างให้ (ชื่อผู้ใช้ + รหัสชั่วคราว) หรือสมัครด้วยรหัสห้อง ยังไม่มีอีเมล Google หรือการสมัครโดยไม่มีห้องเรียน
- **คะแนนทุกตาราง:** ผูกกับ `users.id` จาก session ฝั่งเซิร์ฟเวอร์อยู่แล้ว เบราว์เซอร์ส่ง user id มาเองไม่ได้ จึงต่อยอดได้โดยไม่ย้ายข้อมูล
- **รหัสผ่าน:** ใช้ scrypt (N=16384) และ session เป็นคุกกี้ HttpOnly SameSite=Lax อายุ 12 ชั่วโมง มี CSRF header guard และ rate limit
- **ระบบที่มีอยู่แล้วและนำมาใช้ต่อ:** โหมดผู้เยี่ยมชม และการนำเข้างานของผู้เยี่ยมชม (ตรวจคำตอบใหม่ที่เซิร์ฟเวอร์ พร้อมขอยืนยันก่อน) จึงใช้กับบัญชีอีเมลและ Google ได้ทันที

## สิ่งที่พัฒนา

**ฐานข้อมูล (migration แบบเพิ่มอย่างเดียว ทำงานทุกครั้งที่เริ่มเซิร์ฟเวอร์)**
- `users`: เพิ่ม email, email_verified_at, full_name, student_code, grade_level, room_name, avatar, avatar_url, terms_accepted_at, signup_method และ unique index ของอีเมล
- `auth_identities (provider, subject → user_id)`: เก็บตัวตน Google ด้วย `sub` ไม่ใช้ข้อความอีเมลเป็นตัวระบุ
- `email_tokens`: เก็บเฉพาะ hash ของลิงก์ยืนยันอีเมลและลิงก์ตั้งรหัสผ่านใหม่ ใช้ได้ครั้งเดียว และมีวันหมดอายุ

**เซิร์ฟเวอร์**
- `server/accounts.js`: สมัครด้วยอีเมล, ยืนยันอีเมล, ส่งลิงก์ซ้ำ, ลืมรหัสผ่านทางอีเมล, Google start/callback, โปรไฟล์, เข้าหรือออกห้องเรียน, ตั้งหรือเปลี่ยนรหัสผ่าน, ยกเลิกการเชื่อม Google, ออกจากระบบทุกอุปกรณ์, ส่งออกข้อมูล และลบบัญชี
- `server/google-oidc.js`: Authorization Code + PKCE (S256), state และ nonce ในคุกกี้ HttpOnly ที่เซ็นด้วย HMAC, แลก code ที่เซิร์ฟเวอร์ด้วย client secret, ตรวจลายเซ็น id_token (RS256 กับ JWKS ของ Google) และตรวจ iss / aud / exp / nonce
- `server/mailer.js`: ส่งอีเมลผ่าน SMTP (nodemailer) หรือ Resend โดยลิงก์สร้างจาก `PUBLIC_URL` เท่านั้น เพื่อกันการปลอม Host header
- `server/auth.js`:
  - รหัสผ่านใหม่ใช้ Argon2id (m=19 MiB, t=2, p=1) ผ่าน hash-wasm ซึ่งไม่ต้อง build native
  - hash แบบ scrypt เดิมยังใช้ได้ และอัปเกรดเป็น Argon2id ตอนเข้าสู่ระบบ
- `server/api.js`: เข้าสู่ระบบด้วยอีเมลหรือชื่อผู้ใช้ ปฏิเสธบัญชีอีเมลที่ยังไม่ยืนยัน และส่งข้อมูลรูปโปรไฟล์ไปกับ `/api/me`
- `server/teacher.js` และ `teacher.html`: รายชื่อนักเรียนแสดงวิธีสมัคร ชื่อ–นามสกุล และรหัสนักเรียน เพื่อให้ครูระบุตัวได้
- **การเปิด-ปิดตามการตั้งค่า:** ถ้ายังไม่ได้ตั้งค่า Google หรืออีเมล ปุ่มหรือฟอร์มของส่วนนั้นจะไม่แสดง และเซิร์ฟเวอร์เตือนใน log ตอนเริ่มทำงาน ใน production ถ้าไม่มี `PUBLIC_URL` ระบบจะปิดทั้งสองส่วน

**หน้าเว็บ**
- `public/js/auth.js` เพิ่มหน้าใหม่: `#/login`, `#/register` (แท็บอีเมล / รหัสห้องจากครู), `#/forgot`, `#/verify/…`, `#/reset/…`, `#/auth-result/…`, `#/profile`, `#/terms`, `#/privacy`
- ปุ่มเข้าสู่ระบบเดิมทุกจุดพามาที่หน้าใหม่ และหลังเข้าสู่ระบบจะกลับไปยังหน้าที่ผู้ใช้อยู่ก่อน
- ปุ่ม Google ใช้โลโก้ G สี่สีและพื้นขาวหรือดำตามแนวทางของ Google
- `public/js/parallax.js`: พื้นหลัง 5 ชั้น (gradient, grid + circuit, nodes + links + แพ็กเก็ตวิ่ง, รูปเรขาคณิตลอย, แสง)
  - ใช้ requestAnimationFrame และ CSS transform เท่านั้น ขยับตามความลึก 4–12 px ตามขนาดจอ และหยุดเมื่อไม่ได้แสดงผล
  - บนจอสัมผัสไม่ขยับตามนิ้ว และเมื่อตั้งค่าลดการเคลื่อนไหวจะหยุดนิ่ง
  - ใช้ในหน้า Login/Register และส่วนบนของแดชบอร์ด (ผู้เยี่ยมชมเห็นเป็นหน้าต้อนรับพร้อมปุ่มเริ่มเรียน)

## ส่วนที่ยังต้องตั้งค่าหรือทดสอบเพิ่ม

1. **Google จริง:** ต้องสร้าง OAuth Client และใส่ `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `PUBLIC_URL`, `APP_SECRET`, `NODE_ENV=production` บน Railway ตาม `docs/ACCOUNTS-SETUP.md`
   - การทดสอบนี้ใช้ผู้ให้บริการ OpenID Connect จำลองที่ทำงานตามโปรโตคอลเดียวกัน เพราะสภาพแวดล้อมนี้ติดต่อ Google ไม่ได้
   - หลัง deploy ควรลองเข้าสู่ระบบด้วย Google จริงหนึ่งครั้ง
   - Google อาจไม่ยอมรับโดเมน `*.up.railway.app` ในหน้า Branding ถ้าเกิดกรณีนี้ต้องใช้โดเมนของสถานศึกษาแทน
2. **อีเมลจริง:** ต้องตั้ง `SMTP_URL` (เช่น Gmail App Password) และ `MAIL_FROM` ถ้ายังไม่ตั้ง การสมัครด้วยอีเมลจะปิดไว้ ส่วน Google และรหัสห้องยังใช้ได้
3. **Node.js 20 ขึ้นไป:** nodemailer รุ่นที่แก้ช่องโหว่ต้องการ Node.js 20+ จึงตั้ง `engines` เป็น `>=20` แล้ว Railway จะเลือกเวอร์ชันให้ตามค่านี้
4. **ข้อมูลส่วนบุคคลของผู้เยาว์:** ระบบเก็บข้อมูลเท่าที่จำเป็น และให้ส่งออกหรือลบบัญชีได้เอง ส่วนเรื่องความยินยอมของผู้ปกครองตามกฎหมาย (เช่น PDPA) ควรให้สถานศึกษาตรวจตามนโยบายของตนเอง หน้า privacy ระบุเรื่องนี้ไว้แล้ว
5. **ยังไม่ได้ทำ:**
   - **การเปลี่ยนอีเมลของบัญชี:** ต้องยืนยันอีเมลใหม่อีกรอบ จึงยังไม่เปิดให้ทำ
   - **การอัปโหลดรูปโปรไฟล์:** ตั้งใจไม่เก็บรูปถ่ายนักเรียน ใช้สีพร้อมตัวอักษรแรกของชื่อ หรือรูปจาก Google แทน
