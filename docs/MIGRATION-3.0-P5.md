# Migration Plan: 3.0 Phase 5 (เวอร์ชัน 2.13.0) Skills Portfolio

## 1. สิ่งที่เปลี่ยนในฐานข้อมูล

**เป็นการเพิ่มอย่างเดียว ไม่แก้และไม่ลบข้อมูลเดิม**

| การเปลี่ยน | รายละเอียด | ผลต่อข้อมูลเดิม |
|---|---|---|
| ตารางใหม่ `skill_observations` | หลักฐานที่ครูเห็นจากการปฏิบัติจริงในห้องเรียน ระดับ 1–4 | ไม่มี |
| ตารางใหม่ `portfolio_notes` | ข้อความสะท้อนคิดของนักเรียนและความเห็นครู แยกตามทักษะ | ไม่มี |
| ตารางใหม่ `capstone_reviews` | คะแนน Rubric การนำเสนอและป้องกันโครงงาน | ไม่มี |
| คอลัมน์ใหม่ `classes.require_practice` | `BOOLEAN NOT NULL DEFAULT FALSE` | ทุกห้องได้ค่า `false` จึงทำงานเหมือนเดิม |

**วิธีเปลี่ยน**
- ทั้งหมดอยู่ท้าย `server/schema.sql` เป็นคำสั่ง `CREATE TABLE IF NOT EXISTS` และ `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`
- ระบบรันไฟล์นี้ทุกครั้งที่เซิร์ฟเวอร์เริ่ม การรันซ้ำจึงไม่มีผลเพิ่ม
- ไม่มีการย้ายหรือแปลงข้อมูล (data migration) ใน Phase นี้

**ข้อมูลที่ผูกกับนักเรียน**
- ทั้ง 3 ตารางอ้างอิง `users(id) ON DELETE CASCADE` เมื่อลบบัญชี ข้อมูล Portfolio ของคนนั้นจะถูกลบด้วย ตรงกับตารางคะแนนเดิม
- คอลัมน์ `teacher_id` และ `commented_by` ใช้ `ON DELETE SET NULL` ถ้าลบบัญชีครู หลักฐานของนักเรียนยังอยู่

## 2. ขั้นตอน (ทำตามลำดับ)

1. **สำรองข้อมูลแบบกู้คืนได้** (ทำบนเครื่องที่ติดตั้ง PostgreSQL client หรือใน Railway shell)
   ```
   pg_dump "$DATABASE_URL" -Fc -f netlab-before-2.13.dump
   ```
   บน Railway ใช้ค่า `DATABASE_PUBLIC_URL` ของบริการ Postgres เมื่อรันจากเครื่องตัวเอง หรือกด Backup ในหน้า Postgres ของ Railway ถ้าแพ็กเกจมีให้
2. **สำรองข้อมูลอ่านได้อีกชุด** (JSON ทุกตาราง ทุกแถว)
   ```
   DATABASE_URL="..." node scripts/backup-db.js netlab-before-2.13.json.gz
   ```
   ไฟล์ทั้งสองมีข้อมูลส่วนบุคคลและรหัสผ่านแบบ hash ต้องเก็บเป็นความลับ ห้าม commit และห้ามส่งต่อ
3. **Deploy เวอร์ชัน 2.13.0** เซิร์ฟเวอร์จะเพิ่มตารางและคอลัมน์เองเมื่อเริ่มทำงาน (log แสดง `Database ready.`)
4. **ตรวจหลัง deploy**
   ```
   DATABASE_URL="..." node scripts/backup-db.js --verify netlab-before-2.13.json.gz
   ```
   ทุกตารางเดิมต้องขึ้นว่า `same` (จำนวนแถวเท่าเดิม) ถ้ามีนักเรียนใช้งานระหว่าง deploy จำนวนแถวอาจเพิ่มขึ้นตามปกติ ให้ตรวจว่าไม่มีตารางใดที่แถวลดลง
5. **ทดลองใช้**
   - เปิดหน้าครู → ห้องเรียน → แท็บ "แฟ้มผลงานทักษะ" ต้องเห็นรายชื่อนักเรียน
   - นักเรียนเปิดเมนู "แฟ้มผลงานทักษะ" ได้

## 3. การย้อนกลับ (Rollback)

- **ย้อนเฉพาะโค้ด** (แนะนำ): deploy เวอร์ชัน 2.12.0 กลับไป
  - โค้ดเก่าไม่อ่านตารางใหม่และไม่สนใจคอลัมน์ใหม่ จึงทำงานได้ทันที
  - ข้อมูล Portfolio ที่บันทึกไปแล้วยังอยู่ ถ้ากลับมาใช้ 2.13.0 จะเห็นข้อมูลเดิมครบ
- **ย้อนโครงสร้างด้วย** (ใช้เมื่อจำเป็นจริงเท่านั้น เพราะข้อมูล Portfolio จะหายถาวร): สำรองข้อมูลก่อนตามขั้นที่ 1 แล้วรัน
  ```sql
  DROP TABLE IF EXISTS capstone_reviews, portfolio_notes, skill_observations;
  ALTER TABLE classes DROP COLUMN IF EXISTS require_practice;
  ```
- **กู้คืนทั้งฐานข้อมูล** ในกรณีเลวร้ายที่สุด:
  ```
  pg_restore --clean --if-exists -d "$DATABASE_URL" netlab-before-2.13.dump
  ```

## 4. ผลการซ้อม Migration (รันจริงในเครื่องทดสอบ 14 ต.ค. 2026)

1. สร้างฐานข้อมูลทดสอบ `netlab_mig` ด้วยโค้ดเวอร์ชัน 2.12.0 (Phase 4) แล้วรันชุดทดสอบ API ของเวอร์ชันนั้นให้สร้างข้อมูลจริง ได้ผู้ใช้ 10 คน, task_progress 19 แถว, sim_results 6, quiz_attempts 2 และ sim_submissions 5 รวม 22 ตาราง 131 แถว
2. สำรองด้วย `scripts/backup-db.js` ได้ไฟล์ `before-p5.json.gz`
3. เปิดเซิร์ฟเวอร์เวอร์ชัน 2.13.0 บนฐานข้อมูลนี้ log แสดง `Database ready.` ไม่มี error
4. `backup-db.js --verify` ได้ `same` ครบทั้ง 22 ตาราง
5. เทียบเนื้อหาทุกแถวก่อนและหลังด้วยสคริปต์ ได้ 0 ตารางที่ต่างกัน มีตารางใหม่ 3 ตาราง และ `classes.require_practice` เป็น `false` ทุกแถว
6. ซ้อมย้อนโค้ด: เปิดเซิร์ฟเวอร์เวอร์ชัน 2.12.0 บนฐานข้อมูลที่อัปเกรดแล้ว ระบบเริ่มทำงานปกติ ล็อกอินได้ และอ่านรายชื่อห้องเรียนได้

7. ซ้อมสำรองและกู้คืนแบบไบนารี: `pg_dump -Fc` ฐานข้อมูลที่อัปเกรดแล้ว จากนั้น `pg_restore` ลงฐานข้อมูลใหม่ และตรวจด้วย `--verify` ทั้ง 25 ตาราง ตรงกันทุกตาราง ยกเว้น `sessions` ต่างกัน 1 แถว ซึ่งเป็นแถวที่เกิดจากการล็อกอินทดสอบในข้อ 6 หลังจากสำรองไปแล้ว

**ข้อที่ยังไม่ได้ทำ:** ยังไม่ได้ทดสอบกับฐานข้อมูลจริงบน Railway การสำรองข้อมูลก่อน deploy (ขั้นที่ 1–2) ต้องทำบนระบบจริง

## 5. เพิ่มเติมใน 3.0 Phase 6 (เวอร์ชัน 2.14.0)

- **ตารางใหม่ `sim_tokens_used`** (`nonce` PK, `user_id`, `used_at`) บันทึกว่าโจทย์สุ่มของห้องจำลองข้อใดส่งตรวจไปแล้ว เพื่อให้นับคะแนนครั้งเดียว ระบบลบแถวที่เก่ากว่า 7 ชั่วโมงเอง
  - เป็นการเพิ่มอย่างเดียวเช่นเดียวกับข้างต้น
  - ใช้ขั้นตอนสำรองข้อมูลและ Rollback เดียวกัน
  - ถ้า Rollback โค้ด ตารางนี้ไม่มีผลกับเวอร์ชันเก่า
- **ข้อมูลเนื้อหาที่เปลี่ยน:** คลังข้อสอบ u1-050 และ u2-049 (แบบจับคู่) สลับลำดับตัวเลือกฝั่งขวาให้ไม่ตรงกับลำดับฝั่งซ้าย คู่ที่ถูกต้องเหมือนเดิม
  - คะแนนที่บันทึกแล้วไม่เปลี่ยน
  - ผลกระทบเดียว: ถ้า deploy ระหว่างที่มีการสอบเปิดอยู่และนักเรียนตอบ 2 ข้อนี้ไปแล้ว คำตอบที่บันทึกไว้จะชี้ตัวเลือกผิดตำแหน่ง จึงควร deploy นอกเวลาสอบ
- **ผลต่อผู้ใช้ที่ใช้รหัสผ่านชั่วคราว:** เซิร์ฟเวอร์บังคับให้ตั้งรหัสผ่านใหม่ก่อนทำงานอื่น ตรงกับที่หน้าเว็บบังคับอยู่แล้ว และไม่มีการเปลี่ยนข้อมูล
