# รายงานการปรับปรุง NetLab 2.6 (MASTER PROMPT Phase 1–10)

รายงานนี้สรุปงานตามลำดับความสำคัญ P0 → P3 รายละเอียดการแก้เนื้อหาแต่ละจุดพร้อมแหล่งอ้างอิงอยู่ใน `docs/review/`

## 1. ปัญหาที่พบจริง

| ระดับ | ปัญหา | สถานะ |
|---|---|---|
| P0 | ข้อความแนะนำแบบทดสอบหลังเรียนเขียนว่า "ชุดเดียวกับก่อนเรียน" ทั้งที่ระบบใช้ข้อสอบคู่ขนานตั้งแต่ 2.5 ข้อความนี้มาจากเทมเพลตเดียวที่ใช้ทั้ง 18 สัปดาห์ จึงผิดทุกสัปดาห์ (README ก็เขียนผิดเช่นกัน) | แก้แล้ว ผลหลังเรียนที่ส่งก่อน 2.5 แสดงหมายเหตุว่าใช้ข้อชุดเดิม และเฉลยดึงข้อชุดที่นักเรียนทำจริง |
| P0 | สัปดาห์ 1 สอน "องค์ประกอบ 5 ส่วน" โดยปนอุปกรณ์เครือข่ายเข้ากับองค์ประกอบการสื่อสารข้อมูล ทำให้ขัดกับแผนภาพของบทเดียวกัน | แก้ทั้งบทเรียน แบบทดสอบ ข้อสอบคู่ขนาน และคลังข้อสอบ |

| P2 | แผนภาพกว้าง 640 หน่วยบนมือถือ 390px ตัวอักษรเหลือราว 7–9px | เพิ่มปุ่ม "ขยายภาพ" ทุกแผนภาพ (เต็มจอ ซูม 100/150/200%) |

ฟีเจอร์ที่ตรวจแล้วว่ามีอยู่และทำงานได้ จึงไม่ได้สร้างซ้ำ ได้แก่

- ข้อจำกัดของโหมดผู้เยี่ยมชม
- สารบัญบทเรียนและปุ่มเรียนต่อ
- ระบบทบทวนข้อที่ตอบผิด
- PWA และการใช้งานออฟไลน์
- `topology-sim` ซึ่งจำลองการตัดสายได้อยู่แล้ว จึงสร้าง `topology-cost` แทน

## 5. แบบฝึกหัดและกิจกรรมที่ปรับปรุง

**คลังข้อสอบ: 383 → 433 ข้อที่ใช้งาน (+41 ข้อฉบับเดิมที่เก็บไว้เป็น retired)**
- ข้อสอบใหม่ 50 ข้อ:
  - ติดป้ายชื่อภาพ (`label`) 20 ข้อ เช่น พอร์ตด้านหลังเราเตอร์, ชั้น OSI/TCP-IP, PDU, ช่อง ipconfig, โหมดเครือข่าย VM, ลำดับสิทธิ์ NTFS
  - อ่านผลคำสั่ง (`pre`) 20 ข้อ เช่น `ipconfig /all`, ตาราง MAC ของสวิตช์, `netsh wlan`, `net share`/`net use`, `ip a`, `netstat -ano`, `route print`, `net user`, `id` + `ls -l`
  - สถานการณ์ปฏิบัติ 10 ข้อ
- ตรวจคลังทุกข้อ:
  - เขียนข้อที่ซ้ำกับข้อสอบหลังเรียนใหม่ 41 ข้อ
  - ข้อที่เขียนใหม่ได้รหัสใหม่ ส่วนฉบับเดิมเก็บไว้เพื่อผลสอบเก่า
  - เพิ่มคำอธิบายรายตัวเลือก (why) ให้ข้อปรนัยทุกข้อ ได้แก่ คลังข้อสอบ แบบทดสอบในบทเรียน ข้อสอบคู่ขนาน และแบบฝึกหัดระหว่างเรียน
  - ปรับระดับความยากให้ตรงกับการคิดที่ต้องใช้

**ห้องจำลอง (ภารกิจเดิมยังใช้ได้ทั้งหมด รหัสและคะแนนเต็มเดิม)**
- **Topology**
  - t8 ฝึกต่อเครือข่ายทีละขั้น 7 ขั้น ตรวจจากสภาพเครือข่ายจริง
  - แอนิเมชันแพ็กเก็ตทีละ hop พร้อมเหตุผลที่ล้มเหลว เช่น สายหลุด, พอร์ตปิด, ไม่มี Gateway, Gateway อยู่นอกวง, Router ไม่มีเส้นทาง, IP ซ้ำ, Firewall
- **Subnet**
  - แสดง IP/Mask เป็น 32 บิต พร้อม AND/OR และโหมดสอนทีละขั้น
  - s8 CIDR ข้ามอ็อกเท็ต, s9 VLSM 5–6 วงจาก /22–/23, s10 /30 /31 /32
- **RJ-45**
  - หัวต่อเสมือนจริงพร้อมภาพด้านข้าง
  - c6 เข้าหัวพร้อมตรวจคุณภาพ ได้แก่ คลายเกลียวยาวเกิน, สายไม่สุด, ปลอกไม่อยู่ใต้ตัวกด, split pair
  - c7 อ่านไฟ LAN Tester และทดสอบสายที่ตัวเองเข้าหัว
- **Terminal**
  - โหมดแนะนำ/ท้าทาย (ค่าเริ่มต้นเป็นโหมดท้าทาย ซึ่งให้คะแนนแบบเดิม ส่วนโหมดแนะนำเลือกใช้เองและได้สูงสุด 7/10)
  - เพิ่มคำสั่ง netstat -ano, ss, route/ip route add, ip neigh, ตัวกรอง findstr/grep และ /? --help
  - m9 IP ซ้ำ, m10 บริการที่เปิดฟัง, m11 ไม่มี default route
- **Troubleshoot**
  - x9 IP ซ้ำ, x10 DNS service หยุด, x11 Firewall บล็อก SMB 445, x12 IP ที่ interface ของ Router ผิด, x13 Mask แคบเกิน
  - ตรวจจากสภาพเครือข่ายหลังแก้ + หลักฐานที่เก็บก่อนแก้ และหักคะแนนเมื่อทำของที่ใช้ได้อยู่พัง

## 7. ประเด็นที่ยังไม่ได้ดำเนินการพร้อมเหตุผล

- **ภาพถ่ายอุปกรณ์จริงและภาพหน้าจอจริง:** sandbox ดาวน์โหลดภาพจากเว็บไม่ได้ และภาพจากเว็บต้องตรวจสิทธิ์ทีละภาพ จึงใช้ภาพวาดต้นฉบับแทน ถ้าครูถ่ายภาพอุปกรณ์ในห้องแล็บเอง สามารถเพิ่มเข้าไปได้
- **ทดสอบบนเครื่องจริง:** ยังไม่ได้ทดสอบบน iPhone หรือ Android จริง ใช้การจำลองของ Chromium เท่านั้น และ Firefox/WebKit ทดสอบเฉพาะใน CI ของ GitHub ซึ่งยังไม่ได้รันจริง
- **Troubleshoot x1–x8 ยังให้เลือกสาเหตุจากรายการ:** ต้องแก้ปัญหาในเครือข่ายจริงด้วย แต่ไม่ได้รื้อการตรวจของภารกิจเดิม เพราะมีคะแนนนักเรียนผูกกับรหัสภารกิจเหล่านั้น ภารกิจใหม่ x9–x13 ไม่มีตัวเลือก
- **บันทึกคะแนนห้องจำลองตอนเข้าสู่ระบบ:** ภารกิจใหม่ตรวจในโหมดผู้เยี่ยมชมผ่าน API ส่วนการบันทึกด้วยบัญชีจริงทดสอบผ่าน API test ทั่วไปเท่านั้น
- **ระยะเวลาเปิด 6 GHz ในไทย:** ระบุได้ระดับ "ราวปี 2565" เพราะหาเลขราชกิจจานุเบกษาไม่พบ
- **การปัดคะแนนห้องจำลอง:** API ปัดคะแนนด้วย `Math.round` (9.5 → 10) เป็นพฤติกรรมเดิมที่ไม่ได้เปลี่ยน เพื่อไม่ให้ระบบคะแนนเปลี่ยน
- **ข้อในแบบทดสอบบทเรียนที่ปรับถ้อยคำ:** คะแนนที่บันทึกไว้แล้วไม่ถูกตรวจใหม่ (form B ข้อ 2 ของ w1 เปลี่ยนเป็นคำถามใหม่ แต่เฉลยยังเป็นตำแหน่งเดิม)

## 8. คำแนะนำสำหรับการพัฒนาขั้นต่อไป

1. ทดลองใช้จริงกับนักเรียน 1 ห้องบนมือถือของนักเรียน แล้วเก็บข้อเสนอแนะเรื่องความยาวเนื้อหาและความยากของภารกิจใหม่
2. เพิ่มภาพถ่ายอุปกรณ์จริงที่ครูถ่ายเองในห้องแล็บ ซึ่งไม่มีปัญหาลิขสิทธิ์
3. หลังจากมีข้อมูลนักเรียนจริง ใช้การ์ด "หัวข้อที่นักเรียนส่วนใหญ่ยังไม่เข้าใจ" ปรับเนื้อหาที่นักเรียนพลาดบ่อย
4. พิจารณาย้าย Troubleshoot x1–x8 ไปใช้การตรวจแบบหลักฐาน + สภาพเครือข่าย โดยสร้างเป็นรหัสภารกิจใหม่
5. รัน GitHub Actions หนึ่งครั้งเพื่อยืนยัน Firefox/WebKit
