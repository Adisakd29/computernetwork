## 4. ก่อน deploy ขึ้น Railway (ต้องทำตามลำดับ)

1. **สำรองฐานข้อมูลจริง** ใช้ `pg_dump` หรือปุ่ม Backup ของ Railway แล้วรัน `node scripts/backup-db.js` (`MIGRATION-3.0-P5.md` ขั้นที่ 1–2)
2. **Deploy นอกเวลาสอบ** เพราะข้อสอบแบบจับคู่ 2 ข้อมีการสลับลำดับตัวเลือก
3. **ตรวจค่าใน Railway Variables:** `APP_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `PUBLIC_URL`
   - เมื่อตรวจเว็บจริงครั้งล่าสุด ปุ่ม Google ยังปิดอยู่
   - เว็บจริงยังเป็นเวอร์ชัน 2.8.0
4. **หลัง deploy:** รัน `node scripts/backup-db.js --verify <ไฟล์สำรอง>` แล้วลองใช้งาน 4 อย่าง
   - เข้าสู่ระบบด้วย Google
   - หน้าครู
   - แฟ้มผลงานทักษะ
   - Linux VM ใน w11 (ตรวจ CSP)
5. **ถ้า Linux VM บูตไม่ได้** ตั้ง `CSP=report-only` ชั่วคราว แล้วแจ้งกลับ
6. **แจ้งนักเรียน** ว่าแล็บท้ายคาบมีข้อ "ลงมือ" เพิ่ม คะแนนเดิมไม่หาย แต่คะแนนเต็มสูงขึ้น

## 5. ข้อจำกัดรวม (แจ้งตามจริง)

**หลักสูตรและการประเมิน**
- สัดส่วนปฏิบัติยังไม่ถึง 70%
- ระดับทักษะให้น้ำหนักหลักฐานจากครูสูง ความน่าเชื่อถือขึ้นกับดุลยพินิจของครู

**ห้องจำลองและเครื่องจำลอง**
- ห้องจำลองทำงานในเบราว์เซอร์ ข้อมูลที่ใช้สร้างโจทย์จึงอ่านได้จากเครื่องมือนักพัฒนา แต่ไม่มีออบเจ็กต์คำตอบแล้ว และคะแนนตรวจที่เซิร์ฟเวอร์เสมอ
- flag ของภารกิจ Linux VM ซ่อนได้ไม่สมบูรณ์ ควรใช้เพื่อฝึก ไม่ใช่คะแนนสอบ
- Linux VM (v86) ยังไม่ได้ทดสอบการบูตจริงในเครื่องทดสอบ ทั้งก่อนและหลังเพิ่ม CSP

**ยังไม่ได้ทดสอบ:** บนมือถือจริง ด้วยโปรแกรมอ่านหน้าจอ และบนระบบจริงที่ Railway

## 6. ข้อเสนอถัดไป (ยังไม่ได้ทำ)

- **เพิ่มสัดส่วนปฏิบัติ:**
  - เพิ่มภารกิจลงมือทำในสัปดาห์ w1, w3, w7, w15
  - หรือนับภารกิจท้าทายแบบจับเวลาเป็นเวลาปฏิบัติ ซึ่งสคริปต์ยังไม่ได้นับ
- **ความเร็วหน้าบทเรียนยาว:** สร้างหัวข้อบทเรียนทีละส่วน เพื่อลดเวลาค้างของหน้า w4 บนเครื่องช้า
- **การล็อกบัญชี:** เปลี่ยนเป็นหน่วงเวลาเพิ่มขึ้นทีละขั้นต่อบัญชี แทนการล็อก 15 นาที เพื่อไม่ให้นักเรียนล็อกบัญชีเพื่อนในห้องได้
